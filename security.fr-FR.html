Comment Docsly protège vos documents

Mis à jour : 2 août 2026

Ce qui est chiffré

Le contenu des documents est chiffré sur votre appareil avec AES-256-GCM. Les noms de documents, les noms de dossiers et les autres métadonnées ne le sont pas : ils sont stockés en clair dans la base de données locale de l'application. Nous le disons franchement, car un coffre qui prétend chiffrer l'intégralité des données sans le faire vaut moins qu'un coffre qui vous montre où passe la limite.

Où sont les clés

La clé de chiffrement est générée sur votre appareil et conservée dans le Keychain d'iOS ou le KeyStore d'Android. Elle ne quitte jamais l'appareil, n'est jamais placée dans une archive de sauvegarde et ne nous est jamais transmise — il n'existe nulle part où l'envoyer.

Sauvegardes

Une sauvegarde est chiffrée avec une phrase secrète que vous choisissez, sur votre appareil, avant tout envoi. La clé est dérivée par PBKDF2 avec 600 000 itérations ; le format d'archive est DOCSP2. Sans cette phrase secrète, personne ne peut ouvrir l'archive, nous pas davantage. Si vous la perdez, la sauvegarde est irrécupérable — c'est la propriété recherchée, pas un oubli.

Ni serveur, ni compte

Docsly n'a ni comptes ni serveur. Vos documents ne nous parviennent jamais. Lorsque vous sauvegardez sur Google Drive ou iCloud, vous écrivez dans votre propre espace de stockage avec votre propre compte ; nous n'en voyons que les parties vers lesquelles vous dirigez l'application.

Code source

Docsly n'est pas open source. Nous publions cette page à la place, afin que l'essentiel — l'algorithme, la dérivation de clé, l'endroit où les clés sont conservées, ce qui quitte l'appareil — puisse être lu et jugé sans avoir à nous croire sur parole.
